# GigaChat B2B в Tribe

С октября 2026 интеграция настроена на **scope `GIGACHAT_API_B2B`** и **единственную модель `GigaChat-2-Max`**.

## Аутентификация

В файле `/opt/tribe/.env` укажите:

```dotenv
GIGACHAT_AUTH_TOKEN=ВАШ_B2B_AUTHORIZATION_KEY
```

Переменная `GIGACHAT_AUTH_TOKEN` — существующее имя Tribe. Её содержимое соответствует `credentials` в вашем примере с официальным SDK; это **authorization key**, а не уже выданный короткоживущий access token.

Не передавайте ключ в чат, не сохраняйте в git, не пересобирайте образ ради добавления ключа. Для применения изменений `.env` контейнеры нужно пересоздать, например повторным ручным GitHub Actions deploy.

## Что изменено

- GigaChat в `BaseNode` вызывается с `scope="GIGACHAT_API_B2B"`, `timeout=120` и моделью `GigaChat-2-Max`.
- Прямые GigaChat SDK вызовы загрузки и удаления вложений используют тот же scope и timeout.
- В UI для GigaChat нельзя вводить произвольную модель; выбор состоит только из `GigaChat-2-Max`.
- Серверная проверка запрещает вызов других GigaChat моделей, включая устаревшие записи в БД: их нужно изменить в интерфейсе.

## SSL/TLS

Для совместимости с текущей настройкой Tribe остаётся `verify_ssl_certs=False` (как в вашем примере).
**Это отключает проверку сертификата и ослабляет защиту соединения**.
Перед реальными чувствительными данными установить доверенный корневой сертификат для GigaChat и включить проверку; провести интеграционный тест соединения.

## Обновление библиотек

Текущий lock-файл оставлен без изменений до отдельного PR и проверки сборки. В новых версиях `langchain-gigachat` параметр `auto_upload_images` заменён на `auto_upload_attachments`, менять его без обновления SDK нельзя.

Реальный B2B вызов не проверялся: ключ пока отсутствует.
